# Draw the Structure canvas with diagram-js

## Context

The Structure tab draws the graph with a hand-written SVG of fixed size. The product owner wants a full-width drawing tool with zoom, pan, fit, shapes, filtering, multi-select, alignment, snapping, undo and redo, a minimap, auto layout and graphs of several hundred nodes. This ADR first chose Cytoscape.js, a graph visualisation library that has no editing behaviour of its own (connecting, undo, alignment and minimap would each be a separate extension or our own code). The alternatives were extending the SVG by hand, Cytoscape.js and React Flow. The product owner then chose diagram-js, the toolkit behind bpmn-js, because it already provides the editor behaviour and so removes tickets. Nothing had been built on Cytoscape, so the change cost only documents.

## Decision

- Use **diagram-js** (MIT, no watermark; a generic toolkit also used by archimate-js and object-diagram-js) for the canvas. We write a small modeling domain on it: node and connection element types, a renderer that draws shape and colour from the node type and line style and ends from the connection type, and a rules provider that encodes the Metamodel's allowed connections and refuses self-connections and duplicates. diagram-js renders SVG in the DOM and is driven imperatively through its own module system; React renders the surrounding panels, forms and popovers and mounts the canvas in one component.
- Take its editor modules rather than rebuilding them: canvas zoom and scroll, selection, lasso, move, create and connect with context pad and palette, align and distribute, grid snapping, keyboard bindings, overlays and the command stack, plus `diagram-js-minimap`. The exact module names and what each gives are verified in the first canvas ticket before anything relies on them.
- Not provided, so ours or added: auto layout (`elkjs`, loaded lazily), export to PNG and SVG, the panels and lists, the Finnish and English texts and the accessibility layer. The DOM elements make the accessibility layer easier than a canvas element would.
- diagram-js is the view, not the source of truth. The state after an event of a line (ADR-0048) is loaded by a hook that returns plain graph data; an importer turns it into shapes and connections. The canvas never reads versions or events directly, so it works with the present model and with the event timeline.
- Every modeling command runs optimistically in the command stack and is sent as the validated write. If the server refuses it (ADR-0049, a stale version), the command is undone and the person gets a readable message. The command stack is the person's session history, so undo and redo issue the inverse write.
- Performance is not measured or gated; the product owner decided it needs no confirmation. If users later report slowness with large graphs, this ADR is reopened and Cytoscape.js is the fallback.

## Consequences

- Several tickets shrink or merge: undo and redo come with drawing, and alignment, snapping, lasso and the minimap are configuration of existing modules.
- SVG in the DOM is slower than a canvas renderer at large sizes; nothing guards that risk now beyond the reopening rule above. diagram-js has no layout, and its documentation is thinner than a general-purpose library's.
- A change of library later is contained by the importer and the hook, as before.

## Verification (structure-canvas ticket 02)

Done against the installed package, with the code in `frontend/tests/canvas/modules.test.ts` (each module is loaded under a `Diagram` and its service is checked).

- **Installed:** `diagram-js` 15.28.1 (MIT, ESM, types shipped as `lib/**/*.d.ts`, CSS at `assets/diagram-js.css`; no licence or watermark issue; works with React 19 and Vite 6 as a plain import). Its dependencies are `didi` 11, `min-dom` 5.3, `min-dash`, `tiny-svg` 4.1, `inherits-browser`, `object-refs` and `path-intersection`; Shadow uses `tiny-svg` directly and lists it. Node's own test runner cannot load diagram-js (extensionless ESM imports), so its tests run in Vitest with jsdom.
- **Present, verified to load and to provide their service:** `selection`, `move`, `lasso-tool`, `create`, `connect`, `context-pad`, `palette`, `rules`, `modeling`, `align-elements`, `distribute-elements`, `grid-snapping`, `snapping`, `keyboard`, `editor-actions`, `overlays`, `outline`, `hand-tool` (all under `diagram-js/lib/features/`), the command stack (`diagram-js/lib/command`) and the two navigation modules, which live under `diagram-js/lib/navigation/` and are spelled `movecanvas` and `zoomscroll`. Also present and possibly useful later: `keyboard-move`, `keyboard-move-selection`, `search`, `hover-tooltip`, `auto-place`, `space-tool`, and `CroppingConnectionDocking` (used by Shadow to end a connection on a shape's outline).
- **Findings that change how later tickets use them:** (1) `modeling` is not brought in by `distribute-elements`, `grid-snapping` and several others; a Diagram that uses them must include `modeling` itself. (2) `keyboard` binds to the diagram's own `<svg>` and the old `keyboard.bindTo` option is removed (it logs an error), which is the "canvas container, not document" behaviour the design wants; keys fire only while focus is inside the drawing, so text fields in the panels are naturally excluded. (3) The library toggles a selected element off when it is clicked again; Shadow keeps it selected (a click on the background clears). (4) `canvas.removeConnection` alone leaves the connection in its shapes' `incoming` and `outgoing`; the importer detaches both ends. (5) A dragged shape is reparented into the shape under the pointer unless the drop target is forced to the root; `GraphMoveTarget` does that. (6) `RuleProvider.addRule` needs an explicit priority.
- **Navigation (ticket 03):** (7) `zoomScroll` hard-codes a 20 %-400 % range, scrolls on a plain wheel (zoom needs ctrl or cmd) and is only enabled while the pointer is over the drawing, so Shadow replaces its `_handleWheel` with its own (10 %-400 %, wheel and pinch zoom around the pointer). (8) The library's hand tool on Space pans on pointer movement alone and ends at the first press (no press-and-drag), so Shadow takes Space for its own space + drag and leaves the hand tool module for ctrl + drag. (9) `keyboard-move` (ctrl + arrows) is not used; arrows are Shadow's own binding. (10) diagram-js has no touch pan or pinch; `GraphNavigation` adds both with pointer events and the svg gets `touch-action: none`.
- **Minimap:** the package is `diagram-js-minimap` 5.6.0 (MIT; depends on `min-dom`, `min-dash`, `tiny-svg`; not installed yet, ticket 07).
- **Drawing (ticket 05):** (11) the library's `connect` accepts the reverse direction on hover and draws the connection itself; Shadow overrides the hover (forward only) and takes over `connect.end` so a drag and the two-click mode end in one place. (12) Shift + mousedown starts the library's lasso, and `lasso-tool` has no toolbar entry point that starts at the pointer, so the toolbar toggle is Shadow's own mode that starts the lasso on a background press. (13) There is no direct-editing package in diagram-js; naming in place is an input in an `overlays` overlay. (14) A diagram-js command stack cannot be the durable session history here: loads replace optimistic elements and server ids change on re-creation, so the history is a journal of plain steps (`canvas/history.ts`) and the command stack only draws.
- **Reading (ticket 06):** (15) `overlays` positions an overlay from the element's top-left corner in canvas units and, with `scale: false`, draws it at constant size (a `1/scale` transform with a top-left origin), so a screen-pixel offset has to be divided by the zoom; the layer hides itself during a view change and shows again at `canvas.viewbox.changed`, which is debounced by the library, so a pan is told from a zoom by comparing the scale in `canvas.viewbox.changing`. (16) The library has no hover event for the keyboard; focus on the node's `<g>` (`tabindex` 0) is the trigger, through `focusin` and `focusout` on the container. (17) Connections between the same pair of nodes are separated by shifting both ends of the straight line perpendicular to it before `CroppingConnectionDocking` crops it, so no waypoint logic is needed. (18) The popover is not hoverable (no pointer events), so WCAG 1.4.13 "hoverable" is met by repeating its content in the details panel and the list rather than by the popover itself.
- **Missing, and who builds it:** automatic layout (`elkjs`, lazy loaded, ticket 07), PNG and SVG export (ticket 07, serialising the canvas SVG), all React panels, the type list and search (ticket 04), the visually hidden node list and live region (ticket 09), and the server-synchronised undo and redo (ticket 05, on the command stack and `GraphModeling.applyEdit`). Nothing the design relies on is missing from the library, so the decision stands.

## Snap, align, layout, minimap and export (structure-canvas ticket 07)

- **Licence of `elkjs` (checked before it was added).** `elkjs` 0.12.1 declares `EPL-2.0 OR GPL-3.0-or-later` (npm registry and the `LICENSE.md` in the package are the Eclipse Public License 2.0). Shadow elects the **EPL-2.0**. It is a weak copyleft licence: its conditions attach to the EPL-licensed code itself (keep the licence and notices, and offer the source of that code when it is distributed), not to Shadow's own code that calls it. Shadow uses the package **unmodified**, as a normal npm dependency, through its public API (`elk.layout(graph)`), in a lazily loaded bundle chunk, so the combination is a separate work that is only linked at run time. The licence text stays with the package in `node_modules` and the source is public (github.com/kieler/elkjs). No change to Shadow's own licence is needed and nothing has to be released. Reason for accepting: a layered layout is wanted, writing one is far outside this feature, and the licence is a recognised open-source licence with no restriction on commercial SaaS use. If a lawyer's view differs, or the package is ever patched, this is where to reopen it; the fallback is to drop auto layout, which is one button and one file (`canvas/layout.ts`).
- **`diagram-js-minimap` 5.6.0** (MIT, the package name checked on the registry; dependencies `min-dom`, `min-dash`, `tiny-svg`, which are already installed). It ships no types and a CommonJS `main` that Node cannot load next to diagram-js's ES modules, so Vitest is pointed at its ES file (`vitest.config.ts`). Its default export is a diagram-js module, but a module cannot be added to a diagram that already exists, and the code should not be in the first load, so `canvas/minimap.ts` (the only importer, loaded with `import()` on the first opening) builds the `Minimap` class by hand with the diagram's services. Three findings: (19) the injector it needs is the diagram itself, and `translate` is looked up with `get(name, false)`, so the second argument must be passed on; (20) a click or drag on the minimap writes `canvas.viewbox(box)` directly, so the canvas it receives is a `Proxy` whose `viewbox(box)` calls `GraphNavigation.setView` (zoom limits, remembered view); (21) it clones each element's visual when the element is added and skips only elements with `element.hidden`, so nodes of a hidden type would stay in the picture; `_createElement` is wrapped to leave out anything marked `shadow-hidden`, and `refresh()` rebuilds it after the type filter changes. The minimap is closed to begin with (it covers a corner of the drawing), opened by a toolbar toggle, `aria-hidden` (a decorative picture; the node list is the text alternative) and its own English-only toggle is hidden by CSS. Its stylesheet is part of `theme.css` (the build publishes exactly one stylesheet), which is why the package's CSS is imported there and not from the lazy file.
- **Snap to grid.** `grid-snapping` supplies the on/off state (`setActive`) and the grid size (10), but it snaps the pointer, which only lands a node on the grid if it started there (22). `GraphTools.snapMove` therefore rewrites `dx` and `dy` of `shape.move.move` (priority 1100, after the library's snapping at 1200 and before the move reads them at 500) so the dragged node's own top left corner is on the grid; the other selected nodes move by the same amount. Ctrl or Cmd turns it off for one drag. The choice is per person in `localStorage` (`shadow.canvas.snap`, `canvas/snap.ts`, registered in `backend/legal/browser-storage.json` and the storage notices). Arrow-key moves are not snapped.
- **Align** is the library's `align-elements` (left, centre, top, middle; one command). **Distribute** is *not* the library's `distribute-elements` (23): it measures the space with a 5 unit margin inside every box and groups boxes whose ranges overlap, so with four or more nodes the gaps differ by a few units (shown in `tests/canvas/tools.test.ts`). `canvas/arrange.ts` does the arithmetic on plain boxes instead (the first and last node stay, the free space between is shared in equal whole-unit gaps; nothing is done when there is no free space), applied with `GraphModeling.arrange`.
- **One command, one write, one history entry.** Align, distribute and auto layout move nodes through diagram-js commands (`elements.align`, and the Shadow command `shadow.arrange`, which calls `modeling.moveElements` once per node inside one command); the move hook of `GraphModeling` collects them, and `GraphTools` flushes at once instead of waiting for the 400 ms quiet time, so each tool is exactly one `positions` write and one `move` entry in the journal, undone by one Undo. The task text's "one `elements.move`" is not possible for different distances per node; one command wrapping the moves is the equivalent, and the library's own stack also undoes it in one step (tested).
- **Auto layout** (`canvas/layout.ts`, `GraphTools.autoLayout`): the layered algorithm, direction right, 40 between nodes, 90 between layers, separate components packed, input sizes from the drawn boxes (not an assumed 160 x 56). Every drawn node takes part, hidden types too, so nothing lands on top of a node that comes back later. The result keeps the graph's top left corner and is then fitted in view. Connections to unknown nodes and self-connections are left out of the input. A generated 50-node graph (and the 50-node mock in the browser test) comes out without overlapping boxes. It runs only when the button is pressed.
- **A bug found on the way (24), fixed in `GraphLayouter`:** when a node that is the *target* of a connection moves, the library passes `connectionStart: false` for the end that did not move, and `false ?? centre` is `false`, so the connection failed to lay out and the move threw. Dragging a target node, align and layout all hit it. Only real points count as hints now, and the sideways shift of parallel connections is kept when a hint is just the moved node's new centre. A regression test is in `tools.test.ts`.
- **Export** (`canvas/export.ts`). SVG: the canvas's `<svg>` viewport group is cloned with its transform removed; elements marked `shadow-hidden` (a hidden type and its connections), outlines, hit areas and selection classes are removed; a `<style>` element carries the drawing's own rules with the theme colours resolved to values, and a background rectangle and `<title>` are added, so the file looks the same outside the page. The area is the bounding box of the visible nodes plus 24. A search's dimming is kept (it is what is on screen). PNG: that SVG is drawn on a canvas at scale 2 (less when the side would pass 16000 px); it is loaded into the image as a `data:` URL, because the production Content-Security-Policy (`caddy/Caddyfile`) allows images from `'self'` and `data:` but not `blob:` (the Vite dev server has no policy, so the browser tests would not have caught a blob URL). The file download itself uses a `blob:` link, which that policy does not govern. File names are `model-line.svg|png`, each part sanitised (`sanitizeNamePart`: no path or reserved characters, no leading dots, 80 characters at most, reserved Windows names avoided). The export items are in a menu (keyboard: Enter on the button, arrows, Enter).
- The Structure canvas toolbar now holds many buttons: it wraps onto a second row, and on a phone it stays inside the canvas.

Adds dependencies to `docs/architecture/stack.md`: `diagram-js`, `diagram-js-minimap`, `elkjs`. Replaces the earlier Cytoscape.js decision of this ADR.
