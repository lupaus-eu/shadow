## Ownership

- `frontend/` owns browser UI and client-side state. `frontend/src/models/canvas/` is the Structure canvas: `useGraphState.ts` (the one seam that knows lines and events), `ShadowCanvas.tsx` (one diagram-js `Diagram`), `CanvasToolbar.tsx`, `view.ts`, `useCanvasView.ts` and `keymap.ts` (navigation), and `diagram/` (the Shadow domain layer: importer, renderer, layouter, rules, modeling, navigation, keys). It receives plain graph data and reports edits. Its tests are `frontend/tests/canvas/` (Vitest, jsdom).
- `backend/` owns HTTP API behavior.
- `backend/migrations/` owns the Yearclock Alembic history.
- `backend/tests/` owns API and persistence integration tests.
- `authentik/` owns ordered flow bootstrap and versioned Authentik identity configuration.
- `docker/` owns service initialization assets used by Compose.
- `caddy/` owns edge routing.
- `docs/architecture/` owns durable technical context.
- `docs/agents/` owns coding-agent conventions and domain notes.
- `docs/design/` owns durable UI and UX guidance.
- `docs/user/`, `docs/admin/`, `docs/operations/`, and `docs/gdpr/` own
  permanent documentation for their respective audiences.
- `scripts/` owns repository maintenance scripts, such as the `.scratch`
  portfolio generator `scratch-status.py`.
- `.scratch/_PORTFOLIO.md` is generated by `scripts/scratch-status.py`; do not
  edit it by hand.
- `.scratch/` owns feature-specific, changing PRDs, technical designs, domain
  specifications, and tickets; `.scratch/_template/` owns their starting
  templates.
- `docs/end-user-tutorial/` and `docs/runbooks/` contain existing V1 acceptance
  and operational material; maintain relevant content there until it is moved
  to the audience-oriented documentation directories.
